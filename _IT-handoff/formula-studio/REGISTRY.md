# Formula Runtime Data Registry

สถานะ: ร่างสำหรับ review — ยังไม่เปลี่ยนฐานข้อมูลจริง
วันที่: 2026-10-12

## รหัสเจ้าของใบงาน

| ข้อมูล | ความหมาย | ผู้เป็นเจ้าของข้อมูล | ใช้ตัดสินสิทธิ์หรือไม่ |
|---|---|---|---|
| `fs_users.data.email` | อีเมลบัญชีที่ใช้เข้าสู่ระบบ | ระบบบัญชีส่วนกลาง + Formula user profile | เป็นต้นทางของรหัสเจ้าของ |
| `fs_records.data.ownerEmail` | อีเมลเจ้าของใบงานแบบตัวพิมพ์เล็กและตัดช่องว่างแล้ว | เซสชันที่ยืนยันแล้ว / gateway | ใช้เป็นรหัสเจ้าของหลัก |
| `fs_records.data.createdBy` | ชื่อผู้สร้างที่แสดงบนหน้าจอ | ข้อมูลเดิมของใบงาน | ใช้แสดงผลและรองรับข้อมูลเก่าเท่านั้น |
| `fs_records.data.salesOwner` | ชื่อเจ้าของฝ่ายขายที่แสดงบนหน้าจอ | ข้อมูลเดิมของใบงาน | ใช้แสดงผลและรองรับข้อมูลเก่าเท่านั้น |
| `/sb/session.email` | อีเมลของผู้ที่ล็อกอินอยู่จริง | เซสชันที่ gateway ตรวจสอบแล้ว | ใช้เทียบกับ `ownerEmail` |

หลักการสำคัญ: ถ้าใบงานมี `ownerEmail` แล้ว ระบบจะไม่ย้อนกลับไปใช้ชื่อเพื่อให้สิทธิ์อีกต่อไป ชื่อซ้ำกันจึงไม่ทำให้เข้าถึงใบงานผิดคนได้ ใบงานเก่าที่ยังไม่มี `ownerEmail` จะใช้กติกาเดิมชั่วคราวจนกว่าจะผ่านการย้ายข้อมูลที่ตรวจสอบความกำกวมแล้ว

## สถานะข้อมูลระหว่างเปลี่ยนผ่าน

- `legacy-unmigrated`: ยังไม่มี `ownerEmail`; อ่านได้ตามกติกาเดิม แต่ต้องเติมรหัสก่อนการแก้ไขครั้งถัดไป
- `canonical`: มี `ownerEmail` ถูกต้องและตรงกับบัญชีผู้ใช้
- `ambiguous`: ชื่อเดิมตรงกับผู้ใช้มากกว่าหนึ่งคน; ห้ามเดาเจ้าของและห้ามย้ายข้อมูลอัตโนมัติ
- `invalid`: อีเมลไม่ถูกต้องหรือไม่ตรงกับผู้ใช้ที่ยืนยันแล้ว; ให้หยุดและส่งตรวจสอบ

## เส้นทางข้อมูลที่ต้องรักษา

ผู้ใช้ล็อกอิน → เซสชันที่ตรวจสอบแล้ว → gateway → `ownerEmail` ในใบงาน → การมองเห็น/แก้ไข/ลบ → บันทึกประวัติ

ชื่อผู้ใช้ยังส่งไปที่หน้าจอเพื่อให้คนอ่านเข้าใจง่าย แต่ไม่ใช่รหัสความปลอดภัยสำหรับข้อมูลที่เป็น `canonical` แล้ว

## กติกาการเปลี่ยนเจ้าของ

- ผู้ใช้ทั่วไปห้ามเพิ่ม เปลี่ยน หรือลบ `ownerEmail`
- การเติม `ownerEmail` ให้ใบงานเก่าทำได้เฉพาะ migration ที่ผ่านการตรวจสอบและมี backup
- Admin อาจเปลี่ยนเจ้าของได้ตามสิทธิ์เดิม แต่ต้องมีหลักฐานและตรวจว่าอีเมลเป็นผู้ใช้ที่ใช้งานได้
- ถ้าตรวจไม่ได้ว่าใบงานเป็นของใคร ระบบต้องปฏิเสธอย่างปลอดภัย ไม่ให้ผู้ใช้เลือก “ส่งขึ้นระบบ” เอง

## สิ่งที่ยังไม่ทำในเอกสารนี้

- ยังไม่รัน migration กับฐานข้อมูลจริง
- ยังไม่เปลี่ยนข้อมูลใบงานจริง
- ยังไม่ประกาศว่าใบงานทั้งหมดเป็น `canonical`
