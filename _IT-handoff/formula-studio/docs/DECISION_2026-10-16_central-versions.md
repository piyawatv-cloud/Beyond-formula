# DECISION · 2026-10-16 · ประวัติเวอร์ชันที่ระบบกลาง และการลดภาระ localStorage

สถานะ: `PROPOSED` โดย Codex ตามคำสั่งเจ้าของ 16 ต.ค. ค่ำ · ต้อง CODEOWNER approve ใน PR ก่อนขึ้นระบบ

## ข้อเท็จจริง (จาก gateway log 14–16 ต.ค. และ SQL ของ runtime)

- localStorage ของทุกคน ~3.84M/5M: `fs_recbak` 1.50M (39%) · `fs_records` 1.39M · `fs_activities` 0.69M · `fs_chats` 0.25M หลัง slim
- `quota-exceeded → slimmed` 15 ต.ค. 151 ครั้ง, 16 ต.ค. 119 ครั้ง (ทุกคน ทุกวัน) เพราะทุกรอบดึง ห้องแชตทั้ง 243 ห้องกลับมาพร้อมข้อความ แล้ว runtime ค่อยตัด
- ประวัติเวอร์ชันของใบงานอยู่ใน `fs_recbak` ของเครื่องที่แก้เท่านั้น → admin ไม่เห็นเวอร์ชันของ `A02071` ที่มายด์แก้
- ฐานข้อมูลเก็บสำเนา "ก่อนลบ" เท่านั้น (`fs_keep_deleted`) ไม่เก็บ "ก่อนแก้"
- deploy 16 ต.ค. ต้องรันซ้ำ 2 รอบจากเทสต์จับเวลา (Chromium CDP timeout, `large message history…`) ขณะ load เครื่อง 18–41 จากชุดเทสต์ของ Codex บน iMac เดียวกัน

## ทางเลือกและคำตัดสินที่เสนอ

### 1. ประวัติเวอร์ชัน → ระบบกลาง (เลือก ก)

| | ก. trigger เก็บเข้า `fs_archive` เดิม + RPC อ่าน + proxy endpoint | ข. ตารางใหม่ `fs_record_versions` | ค. แก้ sealed ให้ส่งเวอร์ชันขึ้นเอง |
|---|---|---|---|
| schema | ไม่มีตาราง/คอลัมน์ใหม่ (source ค่าใหม่ในตารางที่มีอยู่) | ตารางใหม่ + grants + RLS | release ใหม่ของแอป |
| ความครบ | ทุกทางที่แก้ `fs_records` (RPC, admin REST) ถูกเก็บ | เท่ากัน | เฉพาะที่เบราว์เซอร์ส่งถึง |
| ใครแก้ | จาก `updatedBy` ในก้อนเดิม (แอปเขียนไว้แล้ว) | เท่ากัน | เท่ากัน |
| ความเสี่ยง | `fs_archive` โตตามจำนวนการแก้ (~6KB/ครั้ง) · ต้องไม่ปน `source='fs_records'` ที่แปลว่า "ถูกลบ" (ใช้ `'fs_records_version'`) | เท่ากัน + schema ใหม่ | ช้า |

### 2. `fs_recbak` ต่อเครื่อง → ลดเพดาน 1.5M → 0.5M (เลือก)

ทางเลือกอื่น: ลบทิ้ง (เสียของที่กลางยังไม่มี) หรือคงไว้ (ภาระเท่าเดิม) · เพดานใหม่ยังเก็บได้หลายสิบเวอร์ชัน และของเก่าถูก
ตัดจากงานที่มีเวอร์ชันมากสุดก่อน ตามกลไกเดิมของแอป · ผลคาด: total ต่อเครื่อง ~2.8M

### 3. `fs_chats` → เขียนรูปย่อทุกครั้ง (เลือก)

ตัดเฉพาะข้อความที่กลาง **รับแล้ว** (`sbSnap.msgs`) ซึ่งกลับมาจาก `fs_messages` ทุกรอบดึง · ข้อความที่ยังไม่ส่งเก็บครบ ·
ของในหน่วยความจำไม่ถูกแตะ · ทางเลือกอื่นคือแก้ sealed ให้ดึงเฉพาะห้องที่เห็น (release ใหม่) — ยังทำได้ภายหลัง

### 4. โหลดเครื่องตอน deploy → รอ ไม่ผ่อน (เลือก)

สคริปต์รอ load ≤ 8 สูงสุด 15 นาทีก่อนเริ่มเทสต์ · ไม่ข้ามเทสต์ใด · **ข้อเสนอเพิ่มที่เป็นของเจ้าของ:** ให้ Codex รันชุดเทสต์เต็ม
บนเครื่องอื่นหรือจำกัดเวลา (เช่นหลัง 19:00) เพราะ iMac นี้คือ production

## สิ่งที่ไม่เปลี่ยน

ไม่แตะ key/ฟิลด์ที่ล็อก · ไม่แก้ `fs_records`/`fs_chats` · เบราว์เซอร์ยังไม่มีสิทธิ์อ่าน `fs_archive` ตรง · "กู้คืน" ยังผ่านด่านบันทึกปกติ
(IAM `FORMULA_EDIT`, `ingredientEdit` ถูกบันทึก)

1. อนุมัติแนว ก./เพดาน 0.5M/เขียนรูปย่อ/รอโหลด (หรือแก้ตัวเลข)

3. apply SQL บน production ก่อน deploy runtime (คำสั่งใน handoff)
