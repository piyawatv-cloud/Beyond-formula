# ผลทดสอบสิทธิ์และแจ้งเตือนหลังเริ่มบริการใหม่ — A001T

วันที่ 28 ต.ค. 2026 · สถานะ: ผ่านเฉพาะกรณีทดสอบ / สาเหตุแจ้งเตือนเดิมยังไม่ยืนยัน · ข้อมูลทั้งหมดเป็นข้อมูลจำลอง

## ขอบเขต

คิว SQLite ชั่วคราวใน `mobile-preview/simulation/durable-lab.cjs` ใช้โมเดลหน้าทดลองกับบัญชีจำลองและ Web Push ผ่าน Chrome บน A001T Android 16; ไม่มี production database หรือข้อมูลธุรกิจจริง ทดสอบโทรศัพท์โดยให้ผู้ใช้ปัด Chrome ออกจากแอปล่าสุด ไม่ได้ทดสอบ force-stop, APK หรือ iOS

## หลักฐาน

1. `node mobile-preview/simulation/durable.test.cjs` ผ่าน: เปิดโปรเซสใหม่จริงแล้วไม่สร้าง/ส่งเหตุการณ์เดิมซ้ำ; deny งานนอกสิทธิ์และข้อมูล event ID เปลี่ยน; เปลี่ยน/ถอนสิทธิ์ก่อนส่งและระหว่างส่งให้หลายอุปกรณ์; รายการที่ส่งแล้วไม่ทราบผลหรือค้างระหว่างส่งไม่ถูกส่งซ้ำอัตโนมัติ
2. ทดสอบ A001T ด้วยบริการทดสอบจริงและข้อมูลจำลอง: ผู้ใช้ลงทะเบียนแล้วปัด Chrome ออกจากแอปล่าสุด; คำขอที่ไม่มีสิทธิ์ถูกปฏิเสธ 403; อัปเดตงานส่งหนึ่งครั้ง; หยุดและเริ่มบริการใหม่จริงแล้วส่ง event เดิมได้ `created=false, attempted=0`; แชตใหม่ส่งหนึ่งครั้ง และส่งซ้ำ `attempted=0`; โทรศัพท์มีการแจ้งเตือนทดสอบงานและแชตจาก origin ทดสอบอย่างละหนึ่ง และผู้ใช้ยืนยันเห็นทั้งสองอย่างละหนึ่ง
3. ทดสอบเพื่อทำซ้ำอาการเดิมที่ origin 8799 หลังสมัครใหม่และผู้ใช้ปัด Chrome ออก: บริการรับคำขอทั้งงานและแชต ผู้ใช้และโทรศัพท์พบเฉพาะงาน ไม่พบแชตภายในช่วงตรวจ แม้บริการรายงานส่งคำขอแชตสำเร็จ
4. `node mobile-preview/simulation/scenario.test.cjs`, `push.test.cjs`, `test.cjs`: ผ่าน; การทดสอบนี้ไม่ใช่บัญชีจริงหรือการตรวจ authorization ของ PostgreSQL

## ผลตรวจสาเหตุ

ยังไม่พบ root cause ที่พิสูจน์ได้ อาการเดิมเกิดซ้ำบางส่วน แต่ origin, การสมัครรับแจ้งเตือน, เวลา และสภาพเบราว์เซอร์ไม่ถูกควบคุมให้เหมือนกันทั้งหมด การที่ origin 8810 ผ่านและ 8799 ไม่ครบจึงยังไม่พิสูจน์ว่า origin หรือ service worker เก่าเป็นสาเหตุ บริการตอบรับการส่งไม่ใช่หลักฐานว่าอุปกรณ์แสดงผล ต้องจัดทำการเก็บเหตุการณ์แบบปลอดภัยและทดลองควบคุมตัวแปรต่อก่อน release

## ข้อจำกัด / ข้อค้นพบ

- เมื่อไม่มีคำตอบแน่ชัดหลังส่งออกไป ตัวจำลองเก็บสถานะ `uncertain` และไม่ retry อัตโนมัติ ต้องกำหนดการแก้ไขด้วยคน/วิธีตรวจและนโยบายการ retry ก่อนใช้งานจริง ไม่รับประกัน exactly-once
- ตัวจำลองออกแบบทดสอบเริ่มโปรเซสตามลำดับ ใช้ SQLite ที่ Node ระบุว่า experimental; ไม่พิสูจน์หลายโปรเซส การถอนสิทธิ์ในช่วงระหว่างการตรวจและการส่ง provider หรือความคงทนระดับ production
- ทดสอบสิทธิ์เฉพาะ fixture, ไม่ใช่ Supabase Auth/RLS หรือการปฏิเสธโดยฐานข้อมูลจริง
- การปัดออกจากแอปล่าสุดไม่ใช่ force-stop ใน Settings และยังไม่ได้ทดสอบ APK, iOS, offline, การส่งล่าช้าหรือเปิด notification เข้าระบบจริง
- หยุดบริการ ลบพอร์ต USB ชั่วคราวและข้อมูล/กุญแจทดสอบในเครื่องหลังตรวจแล้ว; การสมัคร/worker บนโทรศัพท์ยังไม่ได้ยืนยันว่าลบแล้ว
- ไม่ได้แก้ production, schema, IAM, secrets หรือ dependency โครงการ และไม่มี UAT/PR/production release
