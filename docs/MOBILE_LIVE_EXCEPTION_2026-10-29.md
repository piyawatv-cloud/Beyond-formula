- **ขอบเขต:** ไคลเอนต์ฝั่งมือถือ (`mobile-preview/`, `android-app/`) ที่ล็อกอินผ่าน `POST /sb/session` และอ่านผ่าน `/sb/rest/v1/fs_records|fs_chats|fs_messages` ที่ประตูข้อมูลเดิมกรองตามสิทธิ์ให้ การอ่าน และการเขียน 3 เส้นทางเดิมของเว็บเท่านั้น: `POST /__formula/approval-change` (อนุมัติ/ถอน), `POST /sb/rest/v1/rpc/fs_save_record` (ปิด/เปิด/Reject แบบ CAS), `POST /sb/rest/v1/fs_messages` (แชต) · เซิร์ฟเวอร์ตรวจสิทธิ์/IAM/เวอร์ชันเอง · ไม่แก้ proxy/SQL/schema/IAM · ยังไม่เปิดสร้าง/แก้ไขงาน
- **ไม่ยกเว้น:** ห้ามฝัง secret/คีย์/รหัสผ่านใน repo, APK หรือ log · ห้ามเก็บรหัสผ่านบนเครื่อง · ทดสอบกับสำเนาฐานแยกก่อนใช้กับ production · ไม่ผ่อนด่านเทสต์ · การสร้าง/แก้ไขใบงาน (job intake) ยังไม่เปิด เพราะต้องใช้โปรโตคอลบันทึกใบงานเต็มของเว็บ
- **ความเสี่ยง:** ไม่มีผู้ตรวจอิสระ; session cookie เป็น bearer token บนเครื่องมือถือ; ข้อมูลธุรกิจจริงแสดงบนอุปกรณ์
- **ควบคุมชดเชย:** เซิร์ฟเวอร์กรองขอบเขตการอ่านตามบทบาท (ไม่เชื่อฝั่งแอป); เก็บ cookie ในพื้นที่ส่วนตัวของแอป (`allowBackup=false`); ออกจากระบบเรียก `DELETE /sb/session`; แจ้งเตือนหน้าจอล็อกเป็นข้อความทั่วไปไม่มีรายละเอียดลูกค้า

- **Rollback:** ลบโหมดระบบจริงออกจาก `index.html` และ `android-app` (ไม่มีการเปลี่ยนบนเซิร์ฟเวอร์)

## แผนโหมดระบบจริง
1. ล็อกอิน: ฟอร์มบนแอป → `POST /sb/session {login,password}` → cookie session ถือในแอป (ไม่เก็บรหัสผ่าน); `GET /sb/session` ได้ name/role/canEdit
2. อ่านข้อมูล: `fs_records`, `fs_chats`, `fs_messages` แบบแบ่งหน้า (≤1000) ตามประตูเดิม; แปลงเป็นโมเดลของแอป (approvals จาก `fs_chats.data.approvals`, ปิดงาน/Reject จาก `fs_records.data`)
3. ขอบเขตผู้ใช้: ใช้ role/name จาก session ไม่ใช่ตัวเลือกบนจอ; ปุ่มที่เขียนกลับปิดไว้พร้อมข้อความ "ยังไม่เปิดเขียนกลับระบบจริง"
4. ซิงก์: ดึงใหม่ตามรอบ/เมื่อเปิดแอป และ `ts` ของข้อความล่าสุด
5. แจ้งเตือนเมื่อปิดแอป: WorkManager ถามข้อความ/งานใหม่ด้วย session เดิม (~15 นาที) แสดงข้อความทั่วไป; ผู้ใช้ปิดแจ้งเตือนหรือ session หมดอายุ → หยุดและแจ้งให้ล็อกอินใหม่
6. ทดสอบ: สคริปต์ e2e กับ proxy + สำเนาฐาน (ไม่ใช่ production) ทุกบทบาท; ผู้ใช้ที่ไม่มีสิทธิ์/session หมดอายุ/เน็ตหลุด
