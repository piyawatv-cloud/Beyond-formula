# รูปแบบไฟล์แคตตาล็อก RM และวิธีตรวจก่อนนำเข้า

เอกสารนี้ส่งต่อให้ Procurement / ผู้ดูแล RD Center ได้ ใช้กับการนำเข้าแคตตาล็อกเข้า Cost Calculator ตาม [ADR 0002](adr/0002-local-first-cost-calculator-without-server-enforcement.md)

## ตรวจไฟล์ก่อน โดยไม่ต้องนำเข้าระบบ

```sh
node "cost calculator by project/tools/check-rm-catalog.js" <ไฟล์.xlsx หรือ .csv>
node "cost calculator by project/tools/check-rm-catalog.js" <ไฟล์> --show-values   # ตรวจการตีความหน่วยราคา
node "cost calculator by project/tools/check-rm-catalog.js" <ไฟล์> --json          # ผลแบบเครื่องอ่าน
```

เครื่องมือนี้ **อ่านอย่างเดียว** ไม่นำเข้าระบบ ไม่เขียนไฟล์ ไม่ต่อเน็ต จึงรันกับไฟล์จริงได้ และใช้ฟังก์ชันตรวจตัวเดียวกับที่แอปใช้จริง (`costParseCatalogRows` ใน `index.html`) รายงานจึงตรงกับผลนำเข้าจริง ไม่ใช่การประมาณ

ค่าราคาและชื่อซัพพลายเออร์ถูกปิดไว้เป็นค่าเริ่มต้น เพื่อให้ส่งผลตรวจต่อให้คนอื่นดูได้

## คอลัมน์ที่ต้องมี

หัวคอลัมน์ไม่สนใจตัวพิมพ์เล็ก/ใหญ่ และมีคอลัมน์อื่นเกินมาได้ **แถวที่ขาดคอลัมน์ใดคอลัมน์หนึ่งจะถูกปฏิเสธ ไม่ใส่ค่าแทนให้** เพราะหน่วยที่ว่างหรือศูนย์ที่เดาเอาจะกลายเป็นต้นทุนผิดโดยไม่มีใครเห็น

| คอลัมน์ | ความหมาย | เงื่อนไข |
|---|---|---|
| `id` | รหัสข้อเสนอราคา | ไม่ซ้ำกัน · นำเข้าซ้ำ id เดิม = อัปเดตทับ |
| `materialId` | รหัสวัสดุ | ต้องมาจากเส้นทางที่ RD รับรอง ห้ามตั้งจากชื่อหรือเลขแถว |
| `tierId` | รหัส Tier ราคา | |
| `vendorId` | รหัสผู้ขาย | |
| `status` | สถานะข้อเสนอ | ต้องเป็น `confirmed` จึงจะคิดต้นทุนได้ |
| `specApproved` | RD รับรอง spec แล้วหรือยัง | `true` / `yes` / `1` / `ใช่` = ผ่าน |
| `currency` | สกุลเงิน | ต้องเป็น `THB` จึงจะคิดต้นทุนได้ |
| `price` | ราคา | ตัวเลข · ใส่ `,` คั่นหลักได้ |
| `priceUnit` | หน่วยของราคา | **`kg` / `g` / `mg` เท่านั้น** |
| `moq` | ปริมาณสั่งซื้อขั้นต่ำ | ตัวเลข |
| `moqUnit` | หน่วยของ MOQ | `kg` / `g` / `mg` |
| `increment` | ขนาดแพ็กที่สั่งเพิ่มได้ทีละ | ตัวเลขมากกว่า 0 |
| `incrementUnit` | หน่วยของ increment | `kg` / `g` / `mg` |
| `leadTimeDays` | ระยะเวลาส่งมอบ (วัน) | ตัวเลขไม่ติดลบ |
| `validUntil` | ราคามีผลถึง | `YYYY-MM-DD` ที่มีอยู่จริง หรือเซลล์รูปแบบวันที่ของ Excel |
| `evidenceRef` | เลขอ้างอิงหลักฐาน | เช่น เลขใบเสนอราคา |

คอลัมน์เสริม (ไม่บังคับ): `version`, `name`, `group`, `spec`, `vendor`, `priceBasisQuantity`

## จุดที่ผิดกันบ่อยที่สุด

**`priceBasisQuantity` — ราคาต่อแพ็ก ไม่ใช่ราคาต่อกิโล**

ถ้าราคาคือ **1,400 บาทต่อถุง 25 กก.** ต้องกรอก:

```
price = 1400 · priceUnit = kg · priceBasisQuantity = 25
```

ไม่ใช่ `price=1400, priceBasisQuantity=1` ซึ่งจะกลายเป็น 1,400 บาท/กก. — **ผิดไป 25 เท่า** และดูไม่ออกจากตัวเลขสรุป ถ้าไม่ระบุคอลัมน์นี้ ระบบถือว่าเป็น 1

ใช้ `--show-values` เพื่อให้เครื่องมือแสดงว่ามันตีความเป็นกี่บาทต่อกิโล แล้วเทียบกับราคาจริง

**หน่วยต้องเป็นหน่วยน้ำหนัก** — `ชิ้น` `pcs` `pack` `ลิตร` ยังใช้ไม่ได้ เพราะเครื่องคำนวณแปลงเป็นน้ำหนักเพื่อคิดกับปริมาณในสูตร วัสดุที่ขายเป็นชิ้นต้องรอการออกแบบเพิ่ม

**วันที่** — เป็นข้อความ `YYYY-MM-DD` หรือเซลล์วันที่ของ Excel ก็ได้ แต่ `2030-02-30` และ `2030-13-01` จะถูกปฏิเสธเพราะไม่มีอยู่จริง

## ข้อจำกัดที่ต้องรู้

เครื่องมือนี้ตรวจ **รูปแบบและความครบถ้วน** เท่านั้น **ไม่ได้ยืนยันว่าราคาถูกต้องตามจริง** และไม่ได้ปิดข้อค้างพบ A01–A10 ของ RD Center ที่ยังสถานะ FAIL อยู่ (ดู `docs/IMPLEMENTATION_PLAN.md`) โดยเฉพาะ:

- การอ่าน **แถวต่อเนื่อง (continuation rows)** ที่ราคาไปอยู่แถวถัดไป — ถ้า export ออกมาแบบตรง ๆ ข้อมูลส่วนนี้มักหาย
- ความเป็นเจ้าของ `materialId` ยังไม่มีข้อตกลง ตอนนี้คนทำไฟล์เป็นผู้กำหนดโดยปริยาย
- ยังไม่มี sync อัตโนมัติ การนำเข้าเป็นการทำด้วยมือทุกครั้ง
