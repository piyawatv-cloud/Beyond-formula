# Cost Calculation — ธรรมนูญของฟีเจอร์ (ซ้อนใต้ CLAUDE.md ราก)

ไฟล์นี้อยู่ **ใต้** `/CLAUDE.md` และ `/AGENTS.md` ของ Formula Studio ถ้าขัดกัน ไฟล์รากชนะเสมอ
ไฟล์นี้บันทึกเฉพาะสิ่งที่โค้ดตอบไม่ได้ — คำตัดสินของเจ้าของระบบจากการย่าง (grill) 2026-09-06

## นี่คืออะไร

ทางเข้าใหม่ของ Cost Calculator สำหรับ RD: ปุ่มเมนูซ้าย → dashboard ใบงานต้นทุน → เปิดงานเป็น tab ภายในแอป
แก้ปัญหาที่ RD ต้องไล่หาปุ่ม "คำนวณต้นทุน" ในตาราง Dashboard ของ Formula ทีละใบ และไม่มีที่ใดแสดงว่า
ใครทำงานต้นทุนใบไหนอยู่ แก้ล่าสุดเมื่อไร · เป้าหมายที่เจ้าของตั้ง: **RD ทำสูตรและรู้ราคาได้ภายใน 30 วินาทีต่อ 1 รายการ**

## ศัพท์เฉพาะ — ห้ามใช้แทนกัน

| คำ | หมายถึง | ไม่ใช่ |
|---|---|---|
| **ใบงาน Formula** | record ใน `fs_records` รหัส `A00001` ที่ Sales/OPC/MKT สร้าง | ใบงานต้นทุน |
| **ใบงานต้นทุน** (cost job) | งานใน `fs_cost` ที่ RD ทำสูตรและราคา มีรหัสภายในของตัวเอง | ใบงาน Formula |
| **ผูก** (bind) | ตั้งช่อง "ใบงาน Formula" ของใบงานต้นทุนให้ชี้ไปที่ `A00001` หนึ่งใบ | การโคลน |
| **งานลอย** (unbound) | ใบงานต้นทุนที่ช่องใบงาน Formula ยังว่าง | งานที่ถูกลบ |
| **โคลน** | สร้างใบงานต้นทุนใหม่จากใบเดิม ติดทุกอย่างมารวมราคาและ PK · เป็นงานลอยจนกว่าจะผูก | revision |
| **revision** | ประวัติการแก้ภายในใบงานต้นทุนเดียว ไม่เปลี่ยนตัวตน | ใบงานใหม่ |
| **เจ้าของสูตร** | RD ที่สร้าง revision แรกของใบงานต้นทุน | Sales ผู้รับผิดชอบ · ผู้สร้างใบงาน Formula |
| **สถานะใบงาน** | เปิดงาน / ปิดงานแล้ว ของใบงาน Formula (`closed`) | สถานะต้นทุน |
| **สถานะต้นทุน** | ร่าง / รอ PK / รอกำหนดราคา / พร้อมเสนอ — คำนวณจากรายการค้าง | สถานะใบงาน |
| **tab** | tab ภายในแอป ในหน้าเบราว์เซอร์เดิม | tab ของเบราว์เซอร์ (session แยก ต้อง login ใหม่) |

`costCapabilities().open` ต้องปฏิเสธ Sales/OPC/Finance/CEO ไม่ใช่แค่ซ่อนปุ่ม

## ขอบเขตความเป็นเจ้าของ

- `fs_records` เป็นของ Formula Studio — ใบงานต้นทุน**อ่าน**ได้ (ชื่อลูกค้า แบรนด์ รูปแบบ สถานะ ผู้แก้ล่าสุด) **ห้ามเขียน**
- `fs_cost` เป็นของฟีเจอร์นี้ — key เสริม มี loader ของตัวเอง ห้ามเขียนก่อน `loadCostStore()` เสร็จ
- `fs_chats` — ใบงานต้นทุนเขียนได้เฉพาะข้อความสรุปยอดหลังบวก (ที่มีอยู่แล้ว) และลิงก์เอกสารสำหรับ CEO
- `fs_reccounter` — **ห้ามแตะ** รหัสภายในของใบงานต้นทุนใช้ตัวนับของตัวเองใน `fs_cost`

## ข้อห้ามถาวร

1. ห้ามเปิดใบงานต้นทุนใน tab เบราว์เซอร์จริง — session อยู่ใน `sessionStorage` แยกต่อ tab จะบังคับ login ใหม่
2. ห้ามผูกใบงานต้นทุนเข้ากับใบงาน Formula ที่มีใบงานต้นทุนอยู่แล้ว — ต้องบอกว่ามีอยู่แล้วและใครเป็นเจ้าของ
3. ห้ามเปลี่ยนรหัสภายในของใบงานต้นทุนเมื่อผูก — รหัสถาวรตลอดอายุ ช่องใบงาน Formula เป็นฟิลด์แยก
4. ห้ามให้ Sales/OPC/Finance/CEO เปิดเครื่องคำนวณได้ทางใด ๆ รวมถึงลิงก์ `#project=` และปุ่มในตาราง Dashboard เดิม
5. ห้ามปิด tab ที่มีค่ายังไม่บันทึกโดยไม่ยืนยัน และห้ามบันทึก revision ให้อัตโนมัติตอนปิด
6. ห้ามแก้ใบงานต้นทุนของใบงาน Formula ที่ปิดงานแล้ว — อ่านอย่างเดียว โคลนไปทำใบใหม่ได้
7. ห้ามใช้ราคาที่โคลนมาโดยไม่ผ่านการตรวจอายุและสถานะใหม่ — ตัวคำนวณตรวจ `validUntil`/`status` ทุกครั้งอยู่แล้ว ห้ามข้าม
8. ห้ามเพิ่มข้อมูลจริง (ชื่อลูกค้า ราคา ผู้ขาย) ลงตัวอย่าง showcase หรือเทสต์

## Stack และคำสั่ง (จากไฟล์ราก)

ไฟล์เดียว `index.html` · vanilla · ไม่มี build · ไม่เพิ่ม dependency · ทำงานใน worktree นี้เท่านั้น

    mkdir -p .runtime
    TMPDIR="$PWD/.runtime" node --test tests/cost-calculator-*.test.js tests/cost-form-reconciliation.test.js 'cost calculator by project/tests/'*.test.js
    TMPDIR="$PWD/.runtime" node tests/run-cost-calculator-browser.js
    TMPDIR="$PWD/.runtime" node harness.js
    TMPDIR="$PWD/.runtime" ./tests/run-sql-tests.sh
    git diff --check

ทุกครั้งที่แก้ `index.html` ต้องเปลี่ยน build stamp บน header
